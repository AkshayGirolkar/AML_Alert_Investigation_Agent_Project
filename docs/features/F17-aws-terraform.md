# F17 – AWS deployment with Terraform

## Goal
Run the same image on AWS (ECS Fargate API + worker, RDS Postgres, ElastiCache Redis, SQS + DLQ, S3, Secrets Manager, CloudWatch), defined entirely in Terraform, reproducible with one `apply` and removable with one `destroy`. Prove it by running a smoke investigation and the F16 sweep against the deployed stack. Cost-bounded: the stack exists for test and demo sessions, not permanently.

## In scope
- **Terraform (`infra/`)**, local state first (S3 backend optional later), `infra/envs/dev.tfvars`, modules or flat files by concern:
  - `network`: VPC, 2 AZs, public subnets (ALB), private subnets (ECS, RDS, Redis). Egress to OpenAI via **one NAT gateway** (dev) or public-subnet Fargate tasks with a locked-down SG (cheaper alternative; see Decisions). VPC endpoints for S3 (free gateway), and optionally SQS/ECR/Secrets/Logs interface endpoints only if NAT is dropped.
  - `data`: RDS PostgreSQL 17 (db.t4g.medium, gp3, encrypted, private, `rds.force_ssl`), parameter group enabling `pg_trgm`/`vector` availability, ElastiCache Redis 7 (single node, in-transit TLS), security groups so only ECS tasks reach them.
  - `queue`: main queue + DLQ matching `SQS_VISIBILITY_TIMEOUT=300` and `maxReceiveCount=3`, CloudWatch alarm on DLQ depth > 0 and on oldest-message age.
  - `registry`: ECR repo (immutable tags by git sha, lifecycle policy keeping last 10).
  - `compute`: ECS cluster; `api` service (2 tasks behind ALB, health check `/health`), `worker` service (no LB), `migrate` as a one-shot task run before each deploy (`alembic upgrade head`, also creates `vector`/`pg_trgm`). Task roles least-privilege (SQS send/receive/delete on the two queues, S3 prefix, read of its own secrets). Logs to CloudWatch (JSON).
  - `secrets`: Secrets Manager entries for DB password (generated by Terraform/RDS-managed), `OPENAI_API_KEY`, `LANGSMITH_API_KEY`, `CONSOLE_DB_PASSWORD`; injected as ECS `secrets`, never in tfvars or state outputs.
  - `storage`: S3 bucket (private, SSE, versioning off) for raw dataset and later report PDFs; public access blocked.
  - `observability`: log groups with retention, CloudWatch alarms (DLQ depth, queue age, ALB 5xx, API task CPU, RDS CPU/connections/free storage, ElastiCache CPU), SNS topic with an email subscription, **AWS Budgets alarm** (create first, in its own tiny stack so `destroy` of the main stack never removes it).
  - `autoscale`: worker service target-tracking on SQS backlog-per-task (visible+in-flight / running tasks), min 1, max 4, scale-in cooldown long enough not to kill in-flight cases; API on CPU. Targets derived from F16 numbers.
- **App changes (minimal, flagged in spec so scope is explicit):**
  - `ensure_queues`: when `AWS_ENDPOINT_URL` is unset, resolve queues with `get_queue_url` and do not create them (Terraform owns them). Unit test with a stubbed client.
  - Accept `REDIS_URL=rediss://...` (verify redis-py TLS works as is; add a test or a note).
  - Extensions: Alembic migration (or documented step) running `CREATE EXTENSION IF NOT EXISTS vector, pg_trgm` so RDS needs no init script.
  - Worker graceful shutdown on SIGTERM (ECS scale-in/deploy sends it): stop receiving, let in-flight cases finish up to `stopTimeout`, else leave messages to reappear. Check whether F07 already does this; add only if missing.
  - `.env.example`: document any new variable.
- **Data on RDS:** restore the ~100k slice (`pg_dump` of the dev DB → S3 → `pg_restore` from a one-off ECS task or bastion-less SSM session) for the demo; the full 5M dataset only for the F16 AWS sweep, loaded with the existing `scripts.load_hi_small` from a one-off task. Documented, scripted (`scripts/aws_seed.sh`), not automatic on apply.
- **Deploy pipeline (GitHub Actions, `.github/workflows/`):**
  - `ci.yml`: ruff, mypy, pytest (unit + Testcontainers Postgres/Redis), `terraform fmt -check` and `validate`, optional `tflint`/`checkov`. (CI does not exist yet; this feature creates it. The F15 replay eval gate is added as a job since it needs no LLM.)
  - `deploy.yml`: on manual dispatch or tag: OIDC role assumption (no long-lived AWS keys), build image, push to ECR with the git sha tag, run the migrate task, `terraform apply` with the new image tag (or `ecs update-service`), wait for services stable, curl `/ready`.
- **Smoke + load on AWS:** `scripts/aws_smoke.py` (enqueue one alert via the ALB, poll to `awaiting_review`/closed, post a decision, verify resume) and the F16 sweep via `loadtest_run --api-url <alb> --force` at worker concurrency 4 and 8, 1 vs 2 tasks, fake LLM; sampler reads CloudWatch instead of `docker stats` (small extension to `app/loadtest/sampler.py`). Results committed as `loadtest/results/example-aws-*.md`.
- **Docs:** ADR `0010-f17-aws-terraform.md` (topology, cost, network choice, secrets, what is deliberately not done), `docs/features/F17-explained.txt`, README "Deploy" and "Cost" sections, a `docs/runbook-aws.md` (apply, seed, smoke, destroy, rotate secret), CLAUDE.md status line, architecture diagram source.

## Out of scope
Multi-region, blue/green or canary deploys, WAF, custom domain + ACM (ALB uses its DNS name over HTTP in dev; HTTPS optional, see Decisions), the F14 console deployment, Bedrock fallback provider (F12 stays OpenAI-only), RDS Multi-AZ/read replicas, Terraform remote-state locking beyond a single user, real-OpenAI load testing on AWS, Cognito unless Decision 3 says otherwise.

## Interfaces
- `terraform apply -var-file=envs/dev.tfvars` creates everything except the budget stack and the ECR images; outputs: `alb_dns_name`, `ecr_repository_url`, `cluster_name`, `queue_urls`, `rds_endpoint` (no secrets).
- Container contract unchanged: same image, `command` selects `uvicorn app.main:app` / `python -m app.worker` / `alembic upgrade head`.
- Env on ECS: `POSTGRES_*`, `REDIS_URL=rediss://…`, `AWS_REGION`, `SQS_QUEUE_NAME`, `SQS_DLQ_NAME`, `LOG_FORMAT=json`, `WORKER_CONCURRENCY`, `WORKER_DB_POOL_SIZE`, `LLM_PROVIDER` (`openai` default; `fake` for the AWS sweep); `AWS_ENDPOINT_URL` unset.

## Rules to keep
- **Cost control first:** budget alarm exists before anything else; dev stack is `destroy`ed after each session; `terraform plan` output with monthly estimate (Infracost optional) goes in the ADR; no resource without a `Project`/`Env` tag.
- **No secrets in git or state outputs;** no long-lived AWS keys in CI (OIDC); security groups least-open; RDS and Redis never public.
- **Same code path as local:** no AWS-only branches in the agent; the only app diffs are those listed above.
- **Idempotent infra and deploy:** `apply` twice is a no-op; migrate task safe to rerun (Alembic).
- **Safe scale-in:** autoscaling and deploys must not lose a case (F07 redelivery covers it; verify in the drill).
- Developer sessions never run `terraform apply` or `destroy` without being asked; the agent produces code and `plan`, the user applies.

## Acceptance criteria
- `terraform fmt -check`, `validate` pass in CI; `plan` against an empty account shows no errors and creates only tagged resources.
- `apply` from scratch yields a reachable `GET /health` and `/ready` (Redis + SQS ok) via the ALB; `destroy` removes everything except the budget stack and ECR repo (or ECR too, per Decision), leaving no billing resources (checklist in runbook: NAT, ALB, RDS, ElastiCache, EIPs, log groups).
- Unit tests: `ensure_queues` uses `get_queue_url` when no endpoint override and still creates queues for LocalStack; migration creates extensions idempotently; SIGTERM handling test if added.
- `scripts/aws_smoke.py` passes against the deployed stack: alert → investigation → `awaiting_review` → approve → resumed and written to memory.
- GitHub Actions: CI green on a PR; deploy workflow ships a new sha to ECS with services stable and `/ready` ok, using OIDC.
- Autoscaling: with a 200-alert burst on the fake LLM, worker tasks scale out above 1 and back in afterwards, 0 errors, 0 duplicates, 0 DLQ.
- Failure drill on AWS (once): stop one worker task mid-run; cases resume after the visibility timeout (as in F16).
- F16 sweep rerun on AWS with a results table (concurrency × tasks → throughput, p95), named first-saturating resource, compared with the local numbers.
- Billing alarm confirmed (test notification received); runbook destroy checklist executed once at the end.

## Decisions (proposed, confirm before building)
1. **Network egress:** single NAT gateway in dev (~$33/month if left on; destroyed after sessions). Alternative: public-subnet Fargate with no inbound, cheaper but less standard. Recommended: NAT, destroy daily.
2. **State and layout:** flat Terraform root with modules for network/data/compute, local state with an optional S3 backend later; budget alarm in a separate root.
3. **Auth:** F11/Cognito not built. Recommended: no Cognito in F17; protect the ALB with a security group allowing only your IP (plus a shared API key header checked by a FastAPI dependency if wanted). Adding Cognito + JWT is its own feature (F11) afterwards. Alternative: do F11 first.
4. **HTTPS:** HTTP on the ALB DNS name, IP-restricted, for dev. ACM + Route 53 only if a domain exists.
5. **Compute sizing:** API 0.5 vCPU / 1 GB × 2; worker 1 vCPU / 2 GB, concurrency 8, one process per task (F16: one process = one core), scale by tasks.
6. **Data:** demo on the 100k slice restored from a dump; full dataset only for the sweep.
7. **LLM on AWS:** real OpenAI for the demo (key from Secrets Manager, rate limiter via ElastiCache), fake LLM for load tests.
8. **Region:** `us-east-1` (matches defaults) unless you prefer otherwise.
9. **Visibility timeout:** keep 300 s; note the 5-minute recovery in the ADR rather than changing it.
