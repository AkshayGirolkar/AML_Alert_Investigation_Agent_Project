# ADR 0004 – F10 Redis

## Status
Accepted

## Decisions
- **Redis is an optimisation, never a dependency.** Every use degrades (see the feature spec), so a Redis outage cannot fail or stall an investigation.
- **Cache the search, not the evidence.** Only the trigram/alias hits are cached, keyed by normalised name and threshold, so one entry serves any account with that name; country and limit are applied after the read. A `sanctions:version` counter invalidates everything on reload.
- **Token bucket in one Lua script using Redis `TIME`**, so workers cannot over-spend and host clock skew is irrelevant. It charges one token per LLM request, since the `LLM` protocol returns no usage; token-aware limits come with F12.
- **Case lock = second guard, Postgres claim stays authoritative.** `SET NX PX` with an owner token, renewed by the heartbeat. A locked case leaves its SQS message for redelivery.
- **No per-customer lock.** The ADR 0003 gap spans `interrupt()` (hours), which a TTL lock cannot cover; `write_memory` stays idempotent per `alert-{id}` key instead.
- **Redis Streams for progress, not pub/sub.** Late or reconnecting SSE clients replay from `Last-Event-ID`. The worker publishes from outside the graph (via `astream(stream_mode="updates")`), because `human_review` re-executes on resume and must stay side-effect free.

## Consequences
- The worker streams node updates and reads the final state from the checkpoint when events are enabled; without a publisher it still uses `ainvoke`.
- The SSE endpoint has been authenticated since F11 (bearer header only; a browser `EventSource` cannot send it, so a console needs fetch-based SSE).
